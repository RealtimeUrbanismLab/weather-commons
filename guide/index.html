Setup guide

Get your own copy of the Realtime Weather sketches and put your first page on the web. Realtime Weather working group, Mondays, 2–23 November 2026.

  • Route A: browser
  • Route B: desktop
  • Add to the shared site
  • Troubleshooting

There are two ways to work. Route A uses only a web browser. Use it today. Route B installs a few tools on your laptop, for later sessions. Both end with a page you can open on any phone.

Before you start

Ask a facilitator for your sketch number. Each breakout room has a block: 10–19, 20–29, 30–39 or 40–49. Your number is yours for the whole workshop. Nobody else uses it.

Your sketch is your own project. It can be research you are already doing, or an event from the catalog.

You need a Claude plan (you have one) and about 20 minutes.

Words you will meet

Repository: a project folder that lives on GitHub, with its full history. Fork: your own copy of someone else's repository, under your account. Pull request (PR): a proposal to add changes to a repository; someone reviews it and merges it, which means accepting it. Branch: a separate line of changes, kept apart until it is merged. Actions: GitHub's robots that run jobs, such as building your site. Pages: GitHub's free web hosting.

Route A: browser only

For everyone, today. Nothing to install.

  1. Make a GitHub account. Go to github.com/signup and follow the steps. Choose your username with care: it will be part of your web address.

    your profile page at github.com/<your username>.

  2. Fork the repository. Open github.com/RealtimeUrbanismLab/weather-commons. Click Fork (top right), then Create fork. Leave the settings as they are.

    a page titled <your username>/weather-commons, with “forked from RealtimeUrbanismLab/weather-commons” under it.

  3. Turn on Actions and Pages in your fork. Forks start with Actions switched off.
    a. In your fork, open the Actions tab. Click I understand my workflows, go ahead and enable them.
    b. Open Settings → Pages (left side). Under Build and deployment, set Source to GitHub Actions.

    the Actions tab lists workflows instead of a warning, and Pages says the source is GitHub Actions.

  4. Connect Claude to your fork. Open claude.ai/code and sign in. When it asks, connect your GitHub account and install the Claude GitHub app. On GitHub's page, choose Only select repositories and pick <your username>/weather-commons. Click Install.

    weather-commons in Claude's repository list.

  5. Ask Claude to make your first page. In claude.ai/code, choose your weather-commons repository and start a new task. Fill in the boxes below, then copy the prompt and paste it in. 
    I'm a participant in the Realtime Weather workshop. This repository is my fork. Please explain each step to me in plain words as you go.

1. Run: node scripts/new-sketch.mjs "<title>" --number <number> --author "<name>"
2. In the new sketch folder, make a first page from the template: my title, my name, one question my sketch asks, and the "Sources and limits" box. Label anything made up as synthetic. Use relative paths only.
3. Read AGENTS.md and follow it. Work only in my sketch folder.
4. Commit with a message that starts with my number, push a branch, and open a pull request in my fork: base <username>/weather-commons, branch main. Not RealtimeUrbanismLab.
5. Give me the link to the pull request, and the address my page will have once it is merged: https://<username>.github.io/weather-commons/<number>-<slug>/

    The words in <angle brackets> fill in as you type. If they stay, replace them yourself before you send. The boxes are kept only until you close this tab.

    Claude works for a few minutes, then gives you a pull request link. If it can't open the pull request itself, it shows a Create PR button. Check that the base is your fork.

  6. Merge it in your fork. Open the pull request link. Read what changed under Files changed. Click Merge pull request, then Confirm merge.

    a purple “Merged” label. In the Actions tab, a job called pages starts running.

  7. Open your live page. Wait about a minute, until the Actions job has a green tick. Then open: 
    https://<username>.github.io/weather-commons/<number>-<slug>/

    The slug is your title in lowercase, with hyphens for spaces. Your fork's front page, https://<username>.github.io/weather-commons/, lists every sketch in your copy.

    your page, on your laptop and your phone. Post the link in the community space.

Today's first page stays in your fork. You can keep changing it: start a new task in claude.ai/code, say what you want, and merge again.

Route B: desktop app

From session 2, for anyone who wants to preview pages before publishing, work with larger data, or use the lab's Box files. You install three tools once. A terminal is a window where you type commands: Terminal on a Mac, Terminal or PowerShell on Windows.

  1. Git (keeps track of changes). In Terminal, run the line below and click Install in the window that opens. 
    xcode-select --install

    If it says the tools are already installed, you're done with this step.

  2. Node (runs the repository's scripts). Download the LTS installer from nodejs.org and open it.
  3. GitHub CLI (talks to GitHub from the terminal). Download the macOS .pkg from cli.github.com and open it.
  4. Close Terminal and open it again, so it finds the new tools.
  1. Git, Node and the GitHub CLI in one line. Open Terminal (or PowerShell) and run: 
    winget install Git.Git OpenJS.NodeJS.LTS GitHub.cli

    Accept the prompts. Git keeps track of changes, Node runs the repository's scripts, and the GitHub CLI talks to GitHub from the terminal.

  2. Close the terminal and open it again, so it finds the new tools.

Then, on both

  1. Sign in to GitHub. Choose GitHub.com, HTTPS and Login with a web browser, and follow the code it gives you. 
    gh auth login
    Then let Git use the same sign-in: 
    gh auth setup-git
  2. Fork and download the repository. This makes a folder called weather-commons where you run it. If you already forked it in Route A, it just downloads your fork. 
    gh repo fork RealtimeUrbanismLab/weather-commons --clone
  3. Open it in Claude. Install the Claude desktop app from claude.ai/download. Open the Code tab and choose the weather-commons folder.

    Claude can now preview your page on your laptop before you publish it. The prompt from Route A step 5 works here too.

Add to the shared site

Your fork is your own site. To add a sketch to the shared site at realtimeurbanismlab.github.io/weather-commons, propose it with a pull request to the shared repository.

  1. On your fork's page on GitHub, click Contribute, then Open pull request.
  2. Check the top line: base is RealtimeUrbanismLab/weather-commons, main. Write two lines about your sketch and click Create pull request.
  3. A facilitator reviews it, may ask for changes, and merges it. Your sketch then appears on the shared site and its index.

Projects start going on the shared site from session 2.

This is public. The repository and both sites can be read by anyone. Your name and GitHub username show on your sketch and in its history. Nothing goes on the shared site until you open a pull request and it is merged: that is how you say yes. If you would rather use a pseudonym, use it for both your GitHub username and the --author name.

Troubleshooting

Nothing happens in the Actions tab after I merge.
Actions are still off in your fork. Open the Actions tab and click I understand my workflows, go ahead and enable them. Then merge again, or open the pages workflow and click Run workflow if it offers one. Stuck? Ask in the community space: https://community.ocean-archive.org/spaces/25478985
The Actions job fails at the deploy step.
Pages isn't set up yet. Go to Settings → Pages and set Source to GitHub Actions. Then open the failed job and click Re-run all jobs. Stuck? Ask in the community space: https://community.ocean-archive.org/spaces/25478985
My page says 404.
For the first minute after a deploy, that is normal. Wait until the Actions job has a green tick, then reload. If it still says 404, check the address: your username, then /weather-commons/, then your folder name, which starts with your number. The folder name is in your fork under sketches/. Stuck? Ask in the community space: https://community.ocean-archive.org/spaces/25478985
Claude can't see my fork, or can't push to it.
The Claude GitHub app doesn't have access to it. On GitHub, open your profile picture → Settings → Applications → Claude → Configure. Under Repository access, add weather-commons and save. Then start a new task in claude.ai/code. Stuck? Ask in the community space: https://community.ocean-archive.org/spaces/25478985
The pull request went to RealtimeUrbanismLab instead of my fork.
GitHub often suggests the shared repository first. No harm done: close that pull request with a short note, then open a new one with base <your username>/weather-commons. Stuck? Ask in the community space: https://community.ocean-archive.org/spaces/25478985
The terminal says “command not found” or “is not recognized”.
The terminal was open while you installed, so it doesn't know about the new tools yet. Close every terminal window, open a new one and try again. On Windows, if that doesn't help, sign out of Windows and back in. Stuck? Ask in the community space: https://community.ocean-archive.org/spaces/25478985
